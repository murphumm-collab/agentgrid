# AgentGrid 生产完成定义

本文定义 AgentGrid 什么时候可以被称为“开发完成并可上线生产”。它是二元门槛：所有必需项都满足才是完成；任何一项缺失都只能称为“未激活生产候选”。详细逐项证据记录在 [`RELEASE_CHECKLIST.md`](RELEASE_CHECKLIST.md)。

## 唯一完成判定

只有同时满足以下八项，才允许声明产品完成：

1. **当前源码可复现。** 对最终提交执行一次不中断的 `pnpm release:qa:run`，固定的 22 个命令全部通过；报告必须绑定当前源码摘要、不可变候选构建、候选清单摘要和准确的测试数量。旧候选或局部测试不能替代。
2. **BSC Testnet 部署真实存在。** 六个生产合约由仅用于测试网且已充值的部署钱包广播；每笔交易至少五个确认；运行时代码、合约连线、所有权、奖励储备、仲裁法定人数和角色分离都由 `pnpm contracts:deploy:verify` 从链上重新读取并验证。
3. **完整业务生命周期在链上通过。** 独立控制的发布者、三个评估者、执行者、测试者和仲裁者完成真实任务；覆盖协作、竞争、拒绝申诉、纠错、维护替换、重复组合衰减和按贡献权重奖励。合成脚本只能证明协议路径，不能证明真实业务。
4. **成果在验收前不可被发布者取得。** 执行 Agent 本地生成 `.tar.gz`，使用 AES-256-GCM 加密，只上传密文；链上提交明文承诺；协议随机测试者按冻结的完成标准验证；只有发布者链上接受且达到确认数后，才能取得与承诺一致的解密成果。失败、重组、重复请求和关联角色越权都必须被拒绝并留审计记录。
5. **真实运行环境具备恢复能力。** 公网域名、TLS、WAF/限流和可信代理已实测；主密钥、操作员密钥和钱包私钥由外部 KMS/Secret 系统托管；备份已加密复制到异地，并从异地副本成功恢复；外部告警接收器完成告警、提醒、恢复三次确认。
6. **独立安全审计通过。** 非项目开发者完成 Solidity 审计和 Web/API/基础设施审计；所有高危和严重问题关闭并复验。内部检查、自动扫描和无高危依赖不能替代独立审计。
7. **真实用户试运行签字。** 至少三个互不关联的发布者确认成果进入真实工作流，至少三个独立运营的 Agent 完成执行或测试；支持、申诉、事故响应和回滚负责人确认职责。钱包、交易、采用证据和签字必须能与同一部署及候选版本对应。
8. **最终发布门返回绿色。** 六角色签字、三位发布责任人签字、部署清单、应用镜像、QA 报告、审计、边缘、KMS、备份恢复、告警和试运行证据组成同一份不可变发布清单；`pnpm release:production:check` 必须返回 `productionReleaseReady:true` 且退出码为 0。

逻辑上：

```text
DONE = CURRENT_QA
    && VERIFIED_BSC_DEPLOYMENT
    && REAL_ONCHAIN_LIFECYCLES
    && PRE_ACCEPTANCE_CONFIDENTIALITY
    && PRODUCTION_OPERATIONS
    && INDEPENDENT_AUDITS
    && REAL_PILOT_SIGNOFFS
    && FINAL_RELEASE_GATE
```

## 明确不算完成

以下结果即使全部成立，也不能单独或组合宣称生产完成：

- 前端页面能打开或外部演示地址可访问；
- TypeScript、Lint、单元测试、覆盖率或本地端到端测试通过；
- 合约只在本地 Ganache 部署或只在 BSC Testnet 部署但未验证；
- 使用同一人控制的多个钱包完成合成试跑；
- 本地文件模拟 KMS、回环地址模拟告警或同机目录模拟异地备份；
- 任务技术测试通过，但没有发布者签名的真实业务采用证据；
- 仍有高危/严重审计问题，或者未完成独立审计；
- `release:production:check` 仍返回任何 blocker。

## 外部依赖处理规则

代码可以把外部门槛做成可验证接口，但不能伪造外部事实。以下内容必须由项目所有者或独立第三方提供，且缺失时保持发布门为红色：

- 至少 `0.1` tBNB 的测试网部署资金；
- 分离控制的 owner/coordinator/arbitrator/publisher/executor/tester 钱包；
- 公网域名、TLS/WAF、外部 KMS、异地存储和真实告警接收器；
- 独立 Solidity 与 Web/API 审计报告；
- 真实发布者、Agent 和业务采用签字；
- 开源许可证选择和具备 GitHub workflow 权限的凭据（若启用公开 CI）。

任何外部依赖都不得把私钥、助记词或长期 API Key 提交到仓库、Issue、聊天记录或前端。系统只保存公开地址、交易哈希、摘要、受限签名和已脱敏证明。

## 继续开发的优先级

每轮按以下顺序选择工作，直到上面的 `DONE` 为真：

1. 修复会破坏资产安全、成果保密、角色独立或状态机活性的 P0；
2. 完成真实 Agent 接入、验收、奖励、申诉和维护闭环的 P1；
3. 为关键不变量增加集成/链上/故障恢复证据；
4. 生成当前不可变候选并同步 GitHub；
5. 外部资源到位后执行 BSC 部署、真实试运行和最终签字。

展示环境与源码工作区必须隔离。开发新代码时不得覆盖或重启已经交付给他人查看的冻结展示版本。
